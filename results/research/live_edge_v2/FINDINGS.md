# What the real GPU experiment establishes

Pinned Qwen Coder30 ran on NVIDIA A100-SXM4-80GB on Modal. The eight real responses
are in [ACTUAL_RESPONSES.md](ACTUAL_RESPONSES.md), with [exact prompts](SYSTEM_PROMPTS.md)
and [GPU receipt proof](GPU_EXECUTION_PROOF.md). No handcrafted replacement was
used. All eight passed structural/evidence/quantum/resource admission; 84 CPU
evaluation runs completed and 30,659 feasible allocations were independently rescored.

## The central finding: useful guidance is not established

Both prompt arms return the exact same physical circuit for every case: a star
centered on the first free qubit, with every exchange sharing beta-group1. The
hub changes from asset0 to asset1 only when asset0 is excluded. This is a constant
template after mandatory domain rebasing, not demonstrated adaptation to numerical
financial features. Group1 is a parameter label, not an angle of one radian.

These diagrams are mixer exchange graphs. The compiler-owned cost layer still
retains all financial interactions; a star mixer does not delete cost terms.
QAOA remains data-dependent through that Hamiltonian and fitted numerical angles.
What is absent here is an observed incremental structural benefit from LLM guidance.

The independent [review](INDEPENDENT_REVIEW.md) constructed the deterministic star
from the saved domains and proved equality of all eight physical GateIRs without
new simulation/allocation calls. Free-text rationales are excluded from this
physical equivalence. A simple rule can reproduce these architectures without an
LLM. Guided versus context-only portfolio results consequently tie on all12 pairs.

Some explanations are incorrect. An exit-case answer describes a hub at frozen
asset0 while its actual edges use free asset1. Another claims weight/sector limits
are preserved by exchanges; only cardinality is preserved by those gates, while
the classical allocator enforces weight constraints. Some strings hit their240-
character schema limit and end mid-sentence despite a normal completion reason.
The prose is not verified financial or quantum reasoning.

## Engineering improvements and preserved failures

- V1 remains **0/8 admitted**. Its GPU produced eight real responses, but duplicated
  evidence labels and contradictory parent/edge citations failed the full contract.
- V2 chooses an edge ID once; the compiler derives its evidence link and schedules
  disjoint exchanges. It avoids an unsupported decoder uniqueness constraint.
  Mapping correctness is enforced by construction, not proof of model intelligence.
- V2 uses the measured unscheduled fixed baseline's resource cap for all methods.
  Original strict scheduled caps excluded the v1 rule/random controls. Changed
  schema, scheduling and caps mean v1-v2 acceptance is not a clean model comparison.
- The first CPU evaluation failed an exact Hamiltonian hash check. Its failed
  reservation/log is retained. Source-bound frozen numerical transport fixes the
 1.0842e-19 platform difference in benchmark-linear statistics while retaining
  the exact original Hamiltonian. Existing exact compiler verification is unchanged.
  CPU recovery reused all original GPU outputs; it did not repeat inference.

## Cost, scope and next decision

V2 worker runtime including setup was407.67s; v1 was278.73s. These measurements do
not establish throughput improvements. V2 used76,782 input/4,870 output tokens.
Combined v1/v2 reservations, including the failed/recovery CPU stages, total
USD4.686350. This is not an invoice; build/preparation overhead is not isolated by
the function reservations or recorded evaluation times. Both GPU batches are real;
QAOA evolution and portfolio allocation were CPU computations, not quantum hardware.

Only opened conditional2010 US estimation data was used. Full-year membership,
artificial policy buckets, dependent mandates/seeds and blocked historical source
admission remain. No financial holdout or continuous investable account test was
opened. COST remains equal-weight B, while allocator feedback scores F.

Keep the verified interface/compiler/numerical-transport improvements. Do not
promote this model as a data-adaptive portfolio circuit designer or launch another
GPU sweep to hide the constant-template result. A future study needs permutation/
feature interventions, a deterministic star control, allocation-faithfulness work
and stronger numerical architecture selection under a new frozen protocol.
