# AGQO technical architecture

The maintained English technical entry point supersedes the original policy-selector
prototype. The historical filename remains compatible with existing references.

## Ownership and data flow

1. Source adapters preserve raw bytes, provenance and checksums. Admission checks
   dated share-class identity, actions, sectors, publication time and aligned returns.
2. Numerical code builds an immutable financial specification and data profile.
   The primary task is mandate-aware tracking/cost repair of an existing account.
3. The support-selection proxy B and allocated objective F remain separate. A shared
   convex allocator assigns weights on each selected support without changing it.
4. The compiler derives and locks direct QUBO/Ising coefficients and explicit slack.
5. The LLM proposes initialization, exchange schedules, parameter sharing and bounded
   circuit edits. It never filters the stock universe or edits financial coefficients.
6. Schema, semantic, invariant, parameter and resource checks precede angle fitting.
   QAOA samples supports; common allocation evaluates the original financial task.
7. Accounts carry positions, cash, drift, fees and next-session execution continuously.
   Reports preserve failures, raw responses, source snapshots and resource accounting.

## Simulation boundary

Full statevectors are capped at 16 total qubits. The conserved-cardinality executor
supports at most 40 asset qubits under a 2,000,000-state cap, including slack. The
30-asset/6-holding case represents all 593,775 supports using classical simulation.
Analytic certificates and small-instance Qiskit comparisons do not imply an independent
full N30/N33 statevector verification or hardware advantage.

## Current qualification boundary

Historical investability remains blocked by missing UTX and incomplete lineage/action/
sector review. The continuous B/F mismatch remains material. No production LLM is
qualified and no independent financial benefit has been established.
